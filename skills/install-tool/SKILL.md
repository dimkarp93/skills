# Новая устанавливаемая программа

Скаффолдер `init_install.sh` и валидатор `check_install.sh` уже реализуют весь чек-лист
из `~/tools/install/CONVENTIONS.md`. Твоя работа — правильно их вызвать и написать
бизнес-логику, а не воспроизводить шаблоны руками: рукописный `justfile` или workflow
почти наверняка разойдётся с конвенциями и отвалится на проверке.

Оба скрипта должны быть в PATH (ставятся через `bootstrap.sh` / `dev-bootstrap.sh`).
Если их нет — зови по абсолютному пути из рабочей копии `~/tools/install`.

## Шаг 1. Собрать параметры

Спроси только то, чего не хватает, остальное бери по умолчанию.

| Что | Флаг | По умолчанию | Когда спрашивать |
|---|---|---|---|
| Язык | `--lang go\|sh` | `go` | если из задачи не ясно |
| Владелец | `--owner OWNER` | — | **обязателен для `--lang go`**, входит в путь модуля |
| Хост | `--host HOST` | `github.com` | для Gitea/самохоста |
| Где создать | позиционный аргумент | — | см. ниже |
| CI | `--ci github\|gitea\|both\|none` | `github` | если хост не github.com |
| Раскладка Go | `--layout cmd\|root` | `cmd` | почти никогда |
| Зеркало | `--upstream URL` | — | только если репозиторий — зеркало |

Выбор языка: `sh` — если программа по сути склейка утилит и её ценность в переносимости
без тулчейна; `go` — если нужны структуры данных, конкурентность, парсинг или
распространение через `go install`.

**Путь резолвится относительно текущего каталога**, а не относительно каких-либо
«корней»: `init_install.sh mytool` создаст `./mytool`. Если человек хочет в свой
рабочий каталог — сначала `cd` туда, либо передай абсолютный путь. Не создавай
репозиторий внутри `~/tools/install` — это рабочая копия самих инсталляторов.

## Шаг 2. Создать скелет

```sh
init_install.sh --lang go --owner <owner> [--host <host>] [--ci both] <name|path>
init_install.sh --lang sh [--ci none] <name|path>
```

Что получится из коробки:

- `versions.txt` = `0.1.0` — единственный источник версии;
- `justfile` с рецептами `build`, `check`, `bump-patch|minor|major`, `release`,
  `install`, `uninstall`, `clean`;
- готовые флаги `--version`, `--origin`, `--buildinfo` (в Go — через
  `github.com/dimkarp93/install-libs/buildinfo`, в sh — подстановкой при сборке);
- `.gitignore` с собранным бинарём и `dist/`;
- workflow релиза со сборкой архивов и `SHA256SUMS`;
- `git init` + первый коммит (отключается `--no-git`);
- в конце автоматически прогоняется `check_install.sh`.

Существующие файлы скаффолдер не перезаписывает (пишет `[skip]`), поэтому поверх
наполовину готового каталога запускай с `--force`.

Если репозиторий уже есть и в нём чего-то не хватает — не досоздавай файлы руками:

```sh
check_install.sh --fix <path>
```

`--fix` дописывает `versions.txt`, `.gitignore`, рецепты `bump-*` и workflow релиза.
`Makefile` он не трогает — там цели добавляй сам.

## Шаг 3. Написать логику, не сломав контракт

Дальше это обычный репозиторий: пиши код в `cmd/<name>/main.go` (Go) или `<name>.sh`.
Единственное, что нельзя трогать, — контракт с инсталляторами:

- `--version` печатает ровно содержимое `versions.txt` — без `v`, без баннера;
- `--origin` печатает канонический `https://host/owner/name` или `local`;
- `--buildinfo` печатает строки `origin=`, `upstream=`, `version=`, `commit=`, `channel=`;
- имя бинаря совпадает с именем каталога репозитория, бинарь кладётся в корень;
- версия меняется только в `versions.txt` и только рецептами `bump-*`.

Инсталляторы парсят этот вывод, так что «улучшение» формата ломает установку и апдейт.
В sh-скелете переменные `VERSION`/`ORIGIN`/`UPSTREAM`/`COMMIT`/`CHANNEL` подставляются
`sed`-ом на сборке — не переименовывай их и не меняй начальные значения.

В Go origin нормализуется библиотекой: не вшивай сырой `git remote get-url origin`,
в нём бывает токен.

## Шаг 4. Проверить

```sh
check_install.sh --build <path>
```

С `--build` он ещё и собирает бинарь и сверяет вывод флагов. Это полный чек-лист
(версия, имя бинаря, рецепты, workflow с `SHA256SUMS`, формат тегов, `.gitignore`,
подстановка origin, требования `go install`). Не пересказывай чек-лист по памяти —
запусти скрипт и покажи вывод: `[FAIL]` = ошибка, `[WARN]` = предупреждение,
код возврата 1, если есть ошибки.

Типовые `[FAIL]` и что с ними делать:

- нет `versions.txt` / `.gitignore` / `bump-*` / workflow → `check_install.sh --fix`;
- имя бинаря не совпало с каталогом → переименуй каталог или `bin` в `justfile`;
- «module path is not a network address» → `--owner`/`--host` были неверны, правь `go.mod`;
- `replace` в `go.mod` → убрать, иначе `go install` не сработает;
- origin не подставляется → `justfile` правился руками, сверься с
  `init_install.sh --emit justfile-go` (или `justfile-sh`).

Сборкой Go занимается скилл `go-build` (актуальность тулчейна, `just build`,
разбор `--buildinfo`) — зови его, если сборка нетривиальна.

## Шаг 5. Установить и релизить

Установка готовой программы:

```sh
local_install.sh <path>        # из локальной рабочей копии
github_install.sh <owner/repo> # из релиза на GitHub
gitea_install.sh <owner/repo>  # из релиза на Gitea
go_install.sh <module>         # через go install
```

Релиз — только по явной просьбе и через скилл `bump-version`: рецепт `bump-*` коммитит
`versions.txt`, ставит тег `vX.Y.Z` и пушит ветку с тегами во все remote, а push тега
запускает CI. Без такой просьбы не коммить, не пушь и не двигай версию.

## Когда правится сам репозиторий инсталляторов

Если меняешь `~/tools/install/*.sh`, изменения не подхватятся, пока не переустановишь:

```sh
~/tools/install/dev-bootstrap.sh              # /usr/local/bin, нужен sudo
~/tools/install/dev-bootstrap.sh --user-only  # ~/.local/bin, без sudo
```

Классические грабли: копии в `~/.local/bin` перекрывают `/usr/local/bin`, потому что
идут в PATH раньше, и человек неделями запускает старую версию. Если поведение скриптов
не сходится с исходниками — сначала проверь это:

```sh
~/.claude/skills/install-tool/scripts/installers-doctor.sh
```

Он показывает, какая копия каждого инсталлятора побеждает в PATH, не устарела ли она
относительно рабочей копии и нет ли затенённых дубликатов. Удаление лишних копий —
действие вне репозитория, так что спроси разрешение.

Шаблоны `workflows/` в самом репозитории генерируются из `init_install.sh`, поэтому
после правки шаблонов — `just sync-workflows`, иначе `just check` упадёт.

## Чего не делать

- Не копировать `justfile`, `main.go` и workflow из других проектов: единственный
  источник — `init_install.sh --emit <template>`.
- Не добавлять комментарии в код, скрипты, `justfile` и workflow.
- Не менять формат вывода `--version` / `--origin` / `--buildinfo`.
- Не редактировать версию мимо `versions.txt` и рецептов `bump-*`.
- Не создавать тулзу внутри рабочей копии инсталляторов.
