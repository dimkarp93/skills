# Поднять версию и опубликовать

Для репозиториев по конвенциям `~/tools/install/CONVENTIONS.md`: версия — в `versions.txt`,
релиз собирает CI по push тега `vX.Y.Z`. Поднять версию значит выполнить ровно такую
последовательность:

1. увеличить компоненту в `versions.txt` (`patch`: 1.2.3 → 1.2.4, `minor`: → 1.3.0, `major`: → 2.0.0);
2. `git commit -m "bump <level>" -- versions.txt` — в коммит идёт только этот файл;
3. `git tag vX.Y.Z`;
4. `git push <remote> HEAD --tags` для каждого remote из `git remote`.

## Как выполнять

Не решай заранее, `just` это или `make`, и не пиши команды руками. Всё определяется в момент
запуска скриптом:

```sh
~/.claude/skills/bump-version/scripts/bump.sh <patch|minor|major> [путь-к-репозиторию]
```

Что делает скрипт:

- переходит в корень git-репозитория, проверяет, что есть `versions.txt`, что в нём нет
  незакоммиченных правок и что HEAD — ветка, а не detached;
- выбирает раннер: `justfile` / `Justfile` / `.justfile` и установленный `just` → `just`,
  иначе `Makefile` / `makefile` / `GNUmakefile` → `make`;
- ищет цель: сначала `bump-<level>`, затем `<level>` (то есть подходит и `just patch`, и
  `make bump-patch`); для just — по `just --summary`, для make — по базе правил `make -pRrq`;
- делает `git fetch --tags` из каждого remote, чтобы не столкнуться с тегом, созданным
  в другом месте (недоступный remote — предупреждение, не ошибка);
- запускает найденную цель. Если цель уже коммитит, ставит тег и пушит (актуальный шаблон
  `init_install.sh`), скрипт только проверяет результат. Если старая цель лишь поменяла
  `versions.txt`, скрипт сам делает коммит, тег и push. Если цели нет вовсе — сам повышает
  `versions.txt` и делает то же самое;
- если тег уже есть — отказывается и возвращает `versions.txt`;
- в конце печатает `old -> new`, коммит, тег и по каждому remote: доехали ли тег и ветка.
  Код возврата ненулевой, если хоть что-то не доехало.

## Перед запуском

- Уровень не назван — бери `patch` и скажи об этом в ответе.
- Ветка не `master` / `main` — спроси, точно ли поднимать версию здесь: тег запустит релиз
  с этого коммита.
- Другие незакоммиченные изменения не мешают и в коммит не попадут — упомяни, что они
  остались в рабочей копии.
- Просьба поднять версию — это и есть разрешение на коммит, тег и push. Ничего сверх этого
  (merge, PR, правки кода, `--force`) не делай.

## После запуска

Кратко отчитайся: репозиторий, `old -> new`, хеш коммита, тег и строки по remote из
вывода скрипта. Если какой-то remote не принял push (например, недоступный self-hosted
Gitea), так и скажи и предложи повторить `git push <remote> HEAD --tags`, когда он оживёт.
Не пересоздавай и не двигай уже запушенный тег.

## Чего не делать

- Не править `versions.txt` вручную в обход скрипта и не коммитить в этот коммит другие файлы.
- Не удалять и не переставлять существующие теги, не пушить с `--force`.
- Не добавлять комментарии в `justfile`, `Makefile` и скрипты.
